# Meridian AI Model Provenance & Clinical Safety Architecture

This document specifies provenance tracking, caching keys, and clinical safety constraints across all AI models integrated into Meridian / ScanLab AI Pro.

## 3. Processing Cache Key (SHA-256)

To meet the CEO's low-latency requirement and avoid redundant compute overhead on repeatedly opened studies, Meridian computes a unique SHA-256 cache key for every processing task:

$$\text{CacheKey} = \text{SHA-256}\Big(\text{studyUID} \,\|\, \text{seriesUID} \,\|\, \text{pipeline} \,\|\, \text{modelVersion} \,\|\, \text{preprocessingVersion}\Big)$$

### Cache Validation Logic:
1. When a user requests an AI analysis or opens a study in the 3D viewer, the API verifies if `.scanlab/derived/<studyId>/manifest.json` exists.
2. The manifest stores the SHA-256 cache key and execution status.
3. If `status == "completed"` and the model version matches, the existing meshes, masks, and metrics are served instantly (sub-50ms latency) without triggering redundant GPU/CPU inference.
4. Reprocessing is triggered only if the user explicitly clicks **Re-run** or if the underlying model version has been updated.

## 4. Zero-Hallucination Policy for Quantitative Metrics

Meridian strictly enforces an anti-hallucination boundary:
1. **Numbers must be physically computed**:
   - Volume ($ml$) is calculated directly as:
     $$\text{Volume} = N_{\text{voxels}} \times \frac{s_x \times s_y \times s_z}{1000}$$
   - Caliper diameter ($mm$) is measured from the 3D bounding extent and convex hull distance.
   - Surface area ($cm^2$) is computed from triangular mesh faces generated by Marching Cubes.
2. **LLM Restrictions**:
   - The report drafting LLM is provided **only** structured numerical values from `metrics/anatomy.json`.
   - The LLM is explicitly forbidden from generating arbitrary lesion dimensions or volumes.
   - Any LLM finding with numerical claims is verified against the structured metrics by the Anatomical QC Engine before presentation to the clinician.
